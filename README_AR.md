# «POS مدقق للمنصات» - دليل التشغيل والإعداد الأمني الشامل

نظام متكامل واحترافي لنقاط البيع (POS)، إدارة المخزون، المبيعات، المرتجعات، وتدقيق تكاليف الشحن وعمولات منصات التجارة الإلكترونية مثل:
- **أمازون (Amazon.eg)**
- **جوميا (Jumia Egypt)**
- **بي تك (B.TECH)**
- **نون (Noon Egypt)**
- إمكانية إضافة أي منصات مخصصة أو منافذ بيع مباشرة بنسب خصم وشحن خاصة بكل منصة.

---

## 1. البنية التقنية والمعمارية

- **الواجهة الأمامية**: React 19 + TypeScript + Tailwind CSS (تصميم عربي كامل RTL متوافق مع كافة الشاشات وأهداف لمس 48px+).
- **قاعدة البيانات الحصرية**: **Google Sheets** دون استخدام أي قاعدة بيانات خارجية أخرى.
- **محرك الربط ومعالجة البيانات**: **Google Apps Script Web App** (`apps-script/Code.gs`) يتولى إنشاء الشيتات تلقائيًا، حفظ السجلات، تشفير كلمات المرور، وإدارة جلسات التوثيق.
- **خادم الوسيط (Proxy Server)**: خادم `server.ts` باستخدام Node.js و Express يعمل على المنفذ `3000`، يتولى إدارة الجلسات، التحقق الصارم من الصلاحيات (Deny by Default)، عزل أسعار الشراء والأرباح، وتمرير الطلبات إلى Google Apps Script لتجاوز قيود CORS وإعادة التوجيه (HTTP 302 Redirect).
- **تطبيق ويب تقدمي (PWA)**: يدعم التثبيت المباشر على الهاتف والحاسوب.

## 2. المصمم هو مالك النظام (System Owner & Designer)

تم تأسيس نظام الصلاحيات على مبدأ أن **«مصمم النظام» هو المالك وصاحب أعلى سلطة في التطبيق** (`role: designer` / `isOwner: true`).

### صلاحيات المالك الحصرية:
1. **هوية الشركة ومظهر التطبيق (`settings.company_appearance`)**:
   - اسم المتجر والشعار (Logo URL أو صورة مرفوعة).
   - الشعار اللفظي (Brand Tagline).
   - بيانات التواصل (الهاتف، البريد، العنوان).
   - الرقم الضريبي ورقم السجل التجاري لطباعتها في الفواتير.
   - اللون الأساسي للعلامة والخط العربي وتطبيقها على جميع شاشات النظام.
2. **إعدادات الفواتير والطباعة (`settings.invoice_print`)**:
   - مقاس الإيصال: 58 مم (طابعات حرارية صغيرة)، 80 مم (طابعات فواتير قياسية)، أو A4 (فواتير ضريبية ورقية).
   - تخصيص الحقول الظاهرة: إظهار/إخفاء الشعار، اسم الشركة، الرقم الضريبي، السجل التجاري، منصة البيع، استقطاعات الخصم والشحن، الباركود، والملاحظات.
   - نصوص الترويسة، التذييل، شروط الاستبدال، وسياسة استقطاع شحن المرتجع.
   - معاينة مباشرة (Live Preview) تفاعلية للإيصال أثناء تعديل الإعدادات قبل الحفظ والطباعة.
3. **إعدادات عرض الأصناف وشاشة المبيعات (`settings.display_customization`)**:
   - التحكم في ظهور الصور المصغرة للأصناف.
   - إظهار أو إخفاء رصيد المخزن وشارات التنبيه (متوفر / منخفض / نفد).
   - تأكيد الفاتورة بنافذة مراجعة قبل الحفظ لمنع أخطاء الإدخال.
4. **المستخدمون والصلاحيات (`permissions.manage` & `users.create`)**:
   - إنشاء المستخدمين وتعيين أدوارهم وصلاحياتهم الفردية.
   - الاطلاع على سجل التدقيق الزمني الشامل `AuditLogs`.
   - **حماية المالك المطلقة**: لا يمكن لأي مدير أو موظف تعديل حساب المالك، أو تعطيله، أو تخفيض صلاحياته، أو حذف حسابه.

## 4. خطوات تهيئة مالك ومصمم النظام الأول (Bootstrap First Developer / Designer)

حفاظًا على الأمان الصارم، **لا يوجد أي مسار أو زر عام في المتصفح يسمح لأي زائر بإنشاء أول مالك أو تسجيل نفسه كمدير**. يتم إجراء التهيئة حصريًا ويدويًا من داخل محرر Google Apps Script وفق الخطوات التالية:

### الخطوة 1: فتح مشروع Google Apps Script
1. افتح جدول Google Sheets الخاص بك.
2. من القائمة العلوية: اضغط **الإضافات (Extensions)** -> **Apps Script**.
3. الصق الكود المعتمد من ملف `apps-script/Code.gs`.

### الخطوة 2: إضافة بيانات المالك في Script Properties المؤقتة
1. من القائمة الجانبية في محرر Apps Script، اضغط على أيقونة **إعدادات المشروع (Project Settings)** ⚙️.
2. انزل إلى قسم **خصائص النص البرمجي (Script Properties)** واضغط **إضافة خاصية (Add script property)**.
3. أضف الخصائص التالية:
   - `DEVELOPER_USERNAME`: اسم المستخدم للدخول (مثال: `admin` أو `عبدالله_المالك`).
   - `DEVELOPER_PASSWORD`: كلمة مرور قوية للمطور والمالك (8 خانات على الأقل تتضمن: حرف كبير A-Z، حرف صغير a-z، رقم 0-9، ورمز خاص مثل `@` أو `#`).
   - `DEVELOPER_NAME`: اسم المالك (مثال: `المهندس عبدالله (مطور ومالك النظام)`).
   - `DEVELOPER_PHONE`: رقم الهاتف للتواصل (اختياري).
4. اضغط **حفظ خصائص النص البرمجي (Save script properties)**.

### الخطوة 3: تشغيل دالة التهيئة الأولية
1. ارجع إلى محرر الكود (`Code.gs`).
2. من القائمة المنسدلة لاختيار الدوال في الأعلى، اختر الدالة:
   `bootstrapFirstDesigner` (أو `bootstrapFirstDeveloper`).
3. اضغط على زر **تشغيل (Run)** ▶️.
4. وافق على صلاحيات الوصول لأول مرة (Authorization).
5. ستشاهد في سجل التنفيذ (Execution Log):
   ```
   ========================================================
   ✅ تم بنجاح إنشاء حساب مصمم ومالك النظام الأول!
   اسم المستخدم: admin
   الاسم: المهندس عبدالله (مطور ومالك النظام)
   الدور: designer (مالك النظام بكامل الصلاحيات)
   تم حذف بيانات التهيئة المؤقتة من Script Properties بنجاح.
   ========================================================
   ```
6. **الأمان الإضافي**: تقوم الدالة تلقائيًا بحذف الخصائص المؤقتة من Script Properties فور اكتمال التشفير، مما يمنع بقاء أي بيانات حساسة أو تكرار استدعاء الدالة.

### الخطوة 4: قواعد تسجيل الدخول وحماية الحسابات
- **اسم المستخدم (Username)**:
  - يقبل الحروف العربية والإنجليزية والأرقام والمسافات والرموز البسيطة (`._-`).
  - يتم تطبيع اسم المستخدم آلياً: إزالة المسافات الزائدة، وتصغير الحروف اللاتينية (lowercase)، بحيث يتطابق `Admin ` و `admin` و `ADMIN`.
- **قواعد كلمات المرور**:
  - **للموظفين والمديرين**: 4 خانات أو أرقام على الأقل لسهولة العمل اليومي على نقاط البيع.
  - **لمصمم ومطور النظام (Developer / Designer)**: 8 خانات على الأقل مع إلزامية الجمع بين الحروف الكبيرة، الصغيرة، الأرقام، والرموز الخاصة.
- **الحماية من التخمين (Brute-Force Protection)**:
  - قفل مؤقت للحساب لمدة 15 دقيقة بعد 5 محاولات دخول خاطئة متتالية.

### الخطوة 5: تسجيل الدخول
- افتح تطبيق الويب، وأدخل اسم المستخدم وكلمة المرور لتسجيل الدخول فورًا بصلاحية مالك النظام.

## 5. هيكل جداول Google Sheets (الـ 11 ورقة الرسمية)

تقوم دالة `setupSheets()` بتهيئة الأوراق التالية تلقائيًا مع دعم الترحيل الآمن للبيانات القديمة:

1. `Items`: الأصناف، أسعار البيع، أسعار الشراء، تكاليف التغليف، أرصدة المخزن، والحالة.
2. `Platforms`: المنصات، نسب الخصم المئوية، والملاحظات.
3. `ItemPlatformCosts`: تكاليف الشحن للصنف على كل منصة، وغرامة شحن المرتجع.
4. `Invoices`: أرقام الفواتير، التواريخ، المنصات، الإجمالي، الخصم، الشحن، الصافي، الربح، والحالة.
5. `InvoiceLines`: لقطة الأسعار والتكاليف التاريخية وقت البيع (Historical Snapshot).
6. `Returns`: سجلات المرتجعات الكلية والجزئية، أسباب الإرجاع، وإجمالي خصم الشحن.
7. `ReturnLines`: أسطر المرتجع التفصيلية وحالة الصنف (يرجع المخزن / تالف).
8. `Users`: المعرف، الهاتف، الاسم، الدور، الـ Salt، الـ PasswordHash، الحالة، عمود `permissionsJson` وعمود `isOwner`.
9. `Settings`: إعدادات المتجر، هوية الشركة `companySettings`، إعدادات الطباعة `invoicePrintSettings`، وإعدادات العرض `displaySettings`.
10. `AuditLogs`: سجل التدقيق الزمني لتوثيق الفاعل، الإجراء، الهدف، وتفاصيل التغيير.
11. `Sessions`: إدارة رموز الجلسات النشطة المشفرة (Tokens) ووقت انتهاء الصلاحية.

## 6. التحقق واختبار رفض الوصول (Security Tests)

تم تصميم النظام لاجتياز اختبارات الأمان الصارمة:

1. **حجب التكاليف والأرباح عن الموظف**:
   - عند تسجيل الدخول بحساب موظف، تُحذف حقول `purchasePrice` و `packagingCost` و `profit` و `unitProfit` من استجابة خادم Node و Google Apps Script تمامًا.
2. **منع التلاعب عبر طلبات الـ HTTP أو Query Parameters**:
   - محاولة إرسال `role=manager` أو `requesterRole=مدير` في رابط الـ GET أو في جسم الـ POST يتم تجاهلها كليًا؛ حيث يعتمد السكربت والخادم حصريًا على الـ Session Token والتحقق من هوية الحساب المسجل في ورقة `Users`.
3. **منع تصعيد الصلاحيات (Privilege Escalation)**:
   - لا يمكن لمدير عادي منح أي مستخدم صلاحية لا يملكها هو نفسه.
   - لا يمكن لمدير عادي تعديل حساب مالك النظام أو تعطيله أو خفض صلاحياته.
   - لا يمكن إنشاء حساب بدور `designer` إلا من قِبل مالك النظام الحالي.
4. **حماية مسار التهيئة**:
   - محاولة استدعاء دالة `bootstrapFirstDesigner` عبر المتصفح أو API تُرفض تلقائيًا مع رسالة خطأ صريحة.

## 8. مسح الباركود، كارت الصنف، والضريبة (تحديث شامل)

### أ. مسح الباركود بالكاميرا في شاشة البيع:
- **زر «مسح بالكاميرا»**: يفتح نافذة ماسح تفاعلية مع إطار مرئي وتوجيه واضح لوضع الباركود.
- **تفضيل الكاميرا الخلفية**: تطلب النافذة كاميرا البيئة (`facingMode: "environment"`) المناسبة للهواتف مع إمكانية التبديل بين الكاميرات وتشغيل الفلاش/الكشاف (Torch) إن كان متاحاً في الجهاز.
- **متطلبات الكاميرا وHTTPS**:
  - تعمل كاميرا المتصفح عبر بروتوكول `HTTPS` أو `localhost` حصرياً وفق معايير أمان المتصفحات (Secure Contexts).
  - عند رفض الإذن أو عدم وجود كاميرا، يعرض النظام تنبيهاً عربياً واضحاً ويوفر بديل الإدخال اليدوي فوراً.
- **دعم الأكواد الشائعة**: EAN-13, EAN-8, UPC-A, UPC-E, Code 128, Code 39, QR Code.
- **الإضافة الفورية للسلة**:
  - عند مسح الكود، يتم البحث في الباركود الأساسي والباركودات الفرعية لجميع الأصناف.
  - إذا وُجد الصنف، يُضاف للسلة مباشرة مع تشغيل نغمة صوتية واهتزاز خفيف، وإذا كان موجوداً مسبقاً في السلة تتم زيادة كميته دون تكرار السطر.
  - إذا لم يوجد، تظهر رسالة عربية واضحة مع إمكانية البحث اليدوي.

### ب. قارئ الباركود الخارجي (USB / Bluetooth Barcode Guns):
- حقل مخصص في شاشة البيع يستقبل إشارات قوارئ الباركود التي تعمل كمحاكاة لوحة مفاتيح (Keyboard Emulation).
- عند مسح الكود أو الضغط على Enter، يُضاف الصنف للسلة فوراً ويُفرغ الحقل استعداداً للمسح التالي.

### ج. حقول كارت الصنف الـ 12:
1. اسم الصنف.
2. رابط الصورة.
3. الباركود الأساسي (فريد مع زر نسخ سريع).
4. باركودات فرعية متعددة (مع إمكانية إضافة وحذف أكواد غير محدودة).
5. اسم المورد.
6. سعر الشراء (للمدير والمصمم فقط).
7. سعر البيع الرسمي.
8. تكلفة التغليف (للمدير والمصمم فقط).
9. نسبة الضريبة % (افتراضي 0%).
10. الكمية بالمخزن (تمنع الأرقام السالبة).
11. تكاليف الشحن لكل منصة.
12. الملاحظات.

### د. إعدادات الضريبة والحسابات الدقيقة:
- **سعر شامل الضريبة أم تُضاف عليه**: إعداد في إعدادات النظام يحدد هل سعر البيع المعروض شامل ضريبة القيمة المضافة (`taxInclusive: true`) أم تُضاف الضريبة فوقه.
- **احتساب عمولة المنصة**: يحدد هل عمولة المنصة تُحسب قبل الضريبة (`before_tax` على السعر الصافي) أم بعدها (`after_tax` على السعر الإجمالي).
- **الضريبة ليست ربحاً للمتجر**: يتم فصل مبالغ الضريبة تماماً ولا تُحتسب كربح للمتجر.
- **حفظ لقطة الضريبة وقت البيع (Snapshot)**: تُسجل الفواتير نسبة وقيمة الضريبة وقت البيع داخل كل سطر لحماية العمليات التاريخية من التغير عند تعديل نسبة الصنف مستقبلاً.
- **التوافق التام مع الأصناف القديمة**: عند نسبة ضريبة 0%، تكون النتيجة مطابقة 100% لمعادلات النظام السابقة.

### هـ. ورقة `ItemBarcodes` في Google Sheets:
- لدعم عدة باركودات فرعية للصنف الواحد، يتم حفظ الأكواد في ورقة `ItemBarcodes` بأعمدة:
  `ID`, `ID الصنف (itemId)`, `الباركود (barcode)`, `نوع الباركود (type)`, `الوصف (label)`, `نشط (active)`, `تاريخ الإنشاء (createdAt)`.
